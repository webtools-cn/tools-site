# 质量标准流程 v2.0 — 存量+新工具统一标准

## 核心原则
1. 每个环节连问5个为什么，想3步：能实现吗？可靠吗？用户满意吗？
2. 质量底线：功能正确+结果对+英文人写+推荐相关+视觉正常
3. 不通过不上线，修完必须验证

---

## 一、存量工具处理流程

### 第1步：问题全量发现（不是抽检）
- 静态扫描：quality_check.py + deep_audit.py
- GSC数据：哪些页面有曝光但0点击
- 视觉验收：浏览器打开，截图，大模型判断
- 功能验收：输入数据→验证结果对不对
- **不抽检，全量扫，一次发现完**

### 第2步：问题根因分类（不是逐个修）
| 根因 | 批量修方案 | 预计时间 |
|:-----|:---------|:---------|
| 通用推荐占位 | 按分类生成同类推荐 | 1分钟 |
| EN中文残留 | 翻译字典批量替换 | 5分钟 |
| intext链接 | 批量替换 | 1分钟 |
| title/description不优 | 按模板批量生成 | 1分钟 |
| 前端无法实现 | 用公开API重写核心逻辑 | 逐个修 |
| 机翻乱码 | 逐页重写EN版 | 逐个修 |
| 功能结果不对 | 手动验证+修复 | 逐个修 |

### 第3步：按影响排序（先修影响最大的）
1. GSC有曝光的页面（排名提升最快）
2. 高搜索量关键词对应的页面
3. 有点击但bounce rate高的页面
4. 其他页面

### 第4步：修完验证（不是宣布完成）
- 静态扫描：0个CRITICAL/HIGH
- 视觉验证：浏览器打开看
- 功能验证：输入数据→结果正确
- GSC验证：排名有没有提升

## 二、新工具开发流程

### 阶段1：需求验证（不验证不开发）

必须回答5个问题：
1. **用户是谁？** CN用户和EN用户需求不同，分别定义
   - CN：什么单位？什么术语？什么场景？
   - EN：什么单位？什么术语？什么场景？
2. **搜索量多少？** 用web_search验证，<1000/月不做
3. **竞品是谁？** 搜关键词看前3名，列出优缺点
4. **我们有什么不同？** 更快/更简单/更全/更好看？
5. **前端能实现吗？** 纯前端？公开API（有CORS/免费/不限速）？还是需要后端？

不通过 → 不开发

### 阶段2：开发（按标准写）

1. **先写需求文档** → .hermes/requirements/{slug}.md
   - CN和EN分别定义用户、单位、术语、FAQ
   - 验收标准：输入什么→输出什么→结果对不对
2. **开发CN版** → 照需求文档写
3. **开发EN版** → 不是机翻！直接用需求文档里的EN内容写
   - 单位用EN用户习惯的（acre不是mu，lb不是jin）
   - 术语用行业标准
4. **相关推荐** → 同类工具，不是3个占位

### 阶段3：验收（6维全过才上线）

| 维度 | 标准 | 验证方法 |
|:-----|:-----|:---------|
| 功能正确 | 输入数据→输出结果正确 | 手动输入已知正确结果验证 |
| 交互合理 | 操作顺手、反馈清晰、错误提示具体 | 像真实用户操作一遍 |
| 视觉正常 | 布局不重叠、文字可读、375px不崩 | 浏览器截图+大模型判断 |
| 语言专业 | EN 0中文+英文自然专业 | 逐段读+术语检查 |
| 内容有用 | 说明准确、FAQ真实、推荐相关 | 判断内容对目标用户有用 |
| SEO合规 | title/description准确、无假评分、AdSense在 | 静态扫描 |

任何一项不通过 → 回去改 → 重新验证 → 直到全通过

### 阶段4：上线后监控

- GSC：排名有没有提升？点击有没有增加？
- GA：停留时间>30秒？Bounce rate<80%？
- 数据不好 → 回去修内容

## 三、铁律

1. **不做凑数工具** — 搜索量<1000不做
2. **EN页面人写** — 不允许机翻
3. **上线必须6维验收** — 任何一项不过不上线
4. **验收必须深** — 功能结果对不对，不是有输出就行
5. **修完必须验证** — 不是宣布完成，是验证通过
6. **批量问题找根因** — 同类问题一次修完，不逐个修
7. **CN和EN需求不同** — 分别定义，不能机翻
8. **质量>数量** — 10个好工具>1000个垃圾
