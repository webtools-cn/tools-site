# 质量标准 v1.0 — 一次性过，不允许返工

> 核心原则：不是"有没有"，是"对不对"。不是"能跑"，是"好用"。

## 一、需求标准（开发前必须通过）

1. **用户是谁**：中文用户和英文用户需求不同，必须分别定义
   - CN用户：用什么单位？什么术语？什么场景？
   - EN用户：用什么单位？什么术语？什么场景？
   - 例：CN用"亩/斤/复合肥"，EN用"acre/lb/NPK ratio"

2. **需求真实**：用户真的需要这个吗？
   - 搜索量验证（不是猜）
   - 竞品分析（搜关键词看前3名）
   - 差异化（我们比竞品好在哪里）

3. **技术可行**：前端能实现吗？
   - 纯前端能做 → 做
   - 需要公开API（有CORS、免费、不限速）→ 可以做，但必须有降级方案
   - 需要后端/爬虫/付费API → 不做

4. **不做清单**：
   - 搜索量为0的
   - 前端无法实现的
   - 已有完美替代且我们没优势的

## 二、开发标准（代码必须满足）

1. **功能正确**：输出结果必须正确，不是"有输出就行"
   - 计算类：用已知结果验证（如1+1必须=2，不能≈2）
   - 转换类：用标准值验证（如1 mile = 1.60934 km）
   - 生成类：输出必须符合规格（如密码长度、格式）
   - 检测类：用真实数据验证（如真实域名查DNS）

2. **单位正确**：CN和EN用各自习惯的单位
   - CN：亩、斤、平方米、摄氏度
   - EN：acre、lb、sq ft、Fahrenheit
   - 不允许EN页面出现"亩""斤"

3. **术语专业**：用行业标准术语，不是机翻
   - CN："复合肥""追肥""底肥"
   - EN："complete fertilizer""top-dressing""base fertilizer"
   - 不允许出现"Calculateuse""Areanumbervalue"这种机翻

4. **交互合理**：
   - 操作步骤最少化
   - 按钮文字清晰（不是"Calculateuse"）
   - 输入有默认值和示例
   - 结果有单位标注
   - 错误提示告诉用户怎么改（不是"请输入有效值"）

5. **内容专业**：
   - 说明文字准确有用，不是废话
   - FAQ回答真实问题，不是凑数
   - 参考数据有来源（如"Based on USDA guidelines"）

## 三、验收标准（上线前必须通过）

### 3.1 功能验收 — 结果必须正确
- [ ] 输入标准测试数据 → 输出与已知正确结果一致
- [ ] 输入空数据 → 友好提示，告诉用户该填什么
- [ ] 输入非法数据 → 友好提示，不报错不崩溃
- [ ] 切换单位/模式 → 结果同步更新
- [ ] 复制/下载/清除 → 都能用

### 3.2 语言验收 — 不是机翻，是人话
- [ ] EN页面0个中文（纯中文+中英混合都算）
- [ ] 英文自然专业，读起来像native speaker写的
- [ ] 术语用行业标准（acre不是mu，lb不是jin）
- [ ] 语言切换链接正确
- [ ] CN页面0个英文残留（标题/按钮/说明）

### 3.3 视觉验收 — 看起来专业
- [ ] 布局正常，无重叠/错位
- [ ] 文字可读，深色背景文字可见
- [ ] 移动端375px不崩
- [ ] 无乱码/占位符/REPLACE_ME
- [ ] 配色协调，看起来专业

### 3.4 交互验收 — 用起来顺手
- [ ] 按钮文字清晰，点了有反馈
- [ ] 结果区域内容可复制/下载
- [ ] 键盘Tab/Enter可操作
- [ ] 加载/处理中有提示
- [ ] 错误提示具体（"请输入面积"不是"输入无效"）

### 3.5 内容验收 — 内容有用
- [ ] 工具说明准确，不是废话
- [ ] FAQ回答真实问题
- [ ] 相关推荐是同类工具（不是3个通用占位）
- [ ] 参考数据有来源

### 3.6 SEO验收 — Google能收录
- [ ] title/description准确
- [ ] 无假评分aggregateRating
- [ ] 无noindex
- [ ] AdSense代码在
- [ ] Schema数据准确

## 四、验证方法 — 不是跑脚本，是真实验证

1. **功能验证**：手动输入数据，对比已知正确结果
2. **视觉验证**：浏览器打开页面截图，大模型判断
3. **语言验证**：逐段读英文，判断是否自然专业
4. **交互验证**：像真实用户一样操作一遍完整流程
5. **内容验证**：判断内容是否对目标用户有用

## 五、不合格 = 不上线

任何一项不通过 → 回去改 → 重新验证 → 直到全部通过 → 才能上线
