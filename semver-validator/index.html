❓ 常见问题

什么是语义化版本（SemVer）？

语义化版本（Semantic Versioning）是一种版本号规范，格式为 MAJOR.MINOR.PATCH。当你做了不兼容的API修改时增加主版本号(MAJOR)，新增向下兼容的功能时增加次版本号(MINOR)，做向下兼容的问题修正时增加修订号(PATCH)。详见 semver.org。

^ (caret) 和 ~ (tilde) 范围有什么区别？

^1.2.3 匹配 >=1.2.3 且 <2.0.0 的所有版本（允许 minor 和 patch 变更）。~1.2.3 匹配 >=1.2.3 且 <1.3.0 的所有版本（仅允许 patch 变更）。这是 npm package.json 中最常用的范围语法。

预发布版本和构建元数据是什么？

预发布版本如 1.0.0-alpha.1，表示主版本之前的测试版，优先级低于正式版。构建元数据如 1.0.0+build.2024，仅用于区分构建，不影响版本优先级，在版本比较时会被忽略。

为什么 "v1.0.0" 不是有效的 SemVer？

SemVer 规范要求版本号必须是纯数字加点号，不允许 "v" 前缀。"v1.0.0" 是 Git tag 的常见写法，但不是合法的语义化版本号。本工具会自动识别并剥离 v 前缀来解析版本号，并在结果中给出提示。

如何使用这个 SemVer Validator？

在"版本号验证"区域输入任何版本号字符串，点击验证即可。你可以一次验证单个版本号，或使用批量验证功能处理多个版本号。版本比较功能可以帮你分析两个版本之间的差异类型（主版本/次版本/修订号变更）。范围匹配功能完全兼容 npm semver 语法。
