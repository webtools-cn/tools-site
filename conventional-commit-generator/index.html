📝 Conventional Commits 生成器

快速生成符合 Conventional Commits v1.0.0 规范的 Git 提交消息，支持 Angular 约定

🏷️ 提交类型

⚙️ 提交详情

💥 Breaking Change（破坏性变更）
修改影响的范围，小写英文，多词用短横线连接
必填，建议使用英文祈使句，首字母小写
用于关联Issue或声明Breaking Change，多个脚注用换行分隔

📋 生成的提交消息

feat: add new feature

🕒 历史记录 （本地存储）

暂无历史记录

📖 使用教程

1. 选择提交类型：feat（新功能）、fix（修复bug）等

2. 可选开启 Breaking Change 标记（破坏性变更会自动升级MAJOR版本）

3. 填写 Scope（可选）、描述（必填）、正文和脚注

4. 实时预览生成的提交消息，一键复制使用

5. 提交命令：git commit -m "<粘贴消息>"

❓ 常见问题

Q: 什么是 Conventional Commits？
A: 一种 Git 提交消息规范，格式为 type(scope): description，让提交历史结构化、可自动化。

Q: Breaking Change 怎么标记？
A: 两种方式：1) type后加感叹号 feat!:；2) footer加 BREAKING CHANGE: 描述。可同时使用。

Q: Scope 应该填什么？
A: 可选。表示修改范围如 auth、parser，小写英文，多词用短横线。

Q: 生成的提交消息能被 commitlint 验证通过吗？
A: 是的！完全符合 Conventional Commits v1.0.0 规范，可以通过 commitlint 等工具的校验。

Q: Footer 应该写什么？
A: 主要用于 Breaking Change 声明和关联 Issue，如 Closes #123。
