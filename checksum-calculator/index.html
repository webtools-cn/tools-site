校验和有什么实际用途？

校验和常用于：验证文件下载完整性、检测数据传输错误、密码存储（使用SHA-256/SHA-512）、数字签名验证、去重检测（相同内容产生相同哈希值）、软件发布校验等场景。

什么是校验和错误（checksum error）？

校验和错误是指从文件实际算出的哈希值，与官方公布的校验值对不上，通常说明文件在下载或传输中损坏、不完整。遇到时应重新下载文件，再用本工具计算 SHA-256 并比对。

遇到校验和错误怎么解决？

请用稳定网络重新完整下载，不要使用断点续传的残缺文件，然后重新计算哈希比对。若多次仍不一致，可更换下载源或浏览器；更换后依旧不一致，通常说明源文件本身已损坏。

关于校验和计算

校验和（Checksum）是通过哈希算法对数据计算出的固定长度摘要值，用于验证数据完整性。本工具支持五种主流算法：MD5（128位，速度快，适用于非安全场景的快速校验）、SHA-1（160位，已不推荐用于安全场景但仍有校验用途）、SHA-256（256位，安全强度高，广泛用于数字签名和密码存储）、SHA-512（512位，安全强度最高，适用于高安全需求场景）、CRC32（32位循环冗余校验，常用于文件传输和压缩文件校验）。所有计算完全在浏览器本地完成，使用Web Crypto API实现SHA系列算法，纯JavaScript实现CRC32，无需上传数据，保障数据隐私安全。

常见使用场景

  • 验证文件下载完整性：下载大文件后，计算SHA-256并与官方提供的校验值比对，确保文件未被篡改或损坏。
  • 检测数据变化：对配置文件或数据库导出计算哈希，定期比对以检测是否被意外修改。
  • 去重检测：对文件计算MD5，相同哈希值的文件内容完全一致，可用于批量去重。
  • 密码哈希：使用SHA-256或SHA-512对密码进行哈希存储（生产环境建议加salt），避免明文存储密码。

MD5、SHA-1、SHA-256 分别用来做什么？

  • MD5（128位，32个十六进制字符）：计算速度快，常用于文件去重、下载完整性快速校验、接口签名（如旧版微信/支付宝签名）。因存在碰撞攻击，不可用于密码或安全场景。
  • SHA-1（160位，40个字符）：Git 版本控制、旧版 TLS 证书、部分接口签名仍在用。已被证明可构造碰撞，新系统不建议用于安全用途。
  • SHA-256 / SHA-512（256/512位）：SHA-2 家族，安全性高，广泛用于数字签名、TLS/SSL、区块链（比特币工作量证明即用SHA-256）和文件发布校验。
  • CRC32（32位，8个字符）：只用于检测传输/存储错误，不是加密哈希，不能防篡改。

为什么我的校验和和别人不一样？

  • 多了空格或换行：末尾的换行符、行首空格、复制时带入的空白都会改变哈希值。文本模式与下载文件模式的结果可能因此不同。
  • 字符编码不同：本工具使用 UTF-8 编码计算。中文或特殊符号按 GBK/UTF-16 等编码得到的结果会不一样。
  • 大小写与格式：十六进制哈希不区分大小写，但比对时不要漏字符或缺位；CRC32 需补齐 8 位。
  • 算法不同：MD5、SHA-1、SHA-256 结果长度不同（32/40/64 字符），请确认对方使用的是同一算法。
  • 文件被改过或下载不完整：重新下载后再计算，仍不一致说明文件内容确实不同。

什么是校验和错误（Checksum Error）？常见场景与排查方法

校验和错误（checksum error / checksum mismatch）指的是：从文件实际内容算出来的哈希值，与官方或发送方公布的校验值对不上。它本身不是病毒，也不代表磁盘一定坏了，而是"收到的数据和原始数据不是同一份"——常见原因是下载中断、传输丢包、存储介质损坏，或文件在发布后被改动过。

常见的报错场景有这样几类：

  • 下载损坏：浏览器或下载器提示"文件已损坏/无法打开"，或者你算出的 SHA-256 与官网公布的校验值不一致，多见于大体积系统镜像（ISO）、游戏客户端和固件。
  • ZIP/RAR 解压失败：解压到一半报"CRC failed""checksum error in xxx.zip""文件被破坏"，说明压缩包在传输中损坏。换成 7-Zip 重新解压、或重新下载，通常即可解决。
  • 安装包校验失败：Windows 安装程序提示"安装文件已损坏""The file is corrupt"，macOS 提示磁盘映像校验失败，或应用商店更新一直卡在"正在校验"。
  • 传输与拷贝出错：网盘上传、FTP 传输、U 盘拷贝之后文件打不开，往往是复制过程被中断，内容不完整。

用本工具排查校验和错误，只需四步：

  1. 拿到官方校验值：在下载页或发布说明里找到 MD5/SHA-256 字符串，很多镜像站会提供 SHA256SUMS 文件。
  2. 上传问题文件：把出错的文件拖进上方"或上传文件"区域，工具会在浏览器本地同时算出 MD5、SHA-1、SHA-256、SHA-512 和 CRC32，文件不会上传到服务器。
  3. 比对结果：在"校验和验证"区选择与官方一致的算法，粘贴官方校验值。显示 ✓ 匹配说明文件完好；显示 ✗ 不匹配就是校验和错误。
  4. 修复：用稳定网络重新完整下载（不要使用断了又续的残缺文件），再次比对。换镜像、换浏览器后仍不一致，基本可以判定源文件已损坏，请联系发布方。

小提示：CRC32 只能发现传输错误，不能防篡改；要确认文件安全请务必使用 SHA-256。如果校验值显示匹配、程序却仍然报错，问题通常不在文件完整性，而在解压工具版本、系统架构（32/64 位）或读写权限。
