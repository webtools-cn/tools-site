❓ Frequently Asked Questions

What is Semantic Versioning (SemVer)?

Semantic Versioning is a versioning scheme using the MAJOR.MINOR.PATCH format. Increment MAJOR for incompatible API changes, MINOR for backward-compatible new features, and PATCH for backward-compatible bug fixes. See semver.org for the full specification.

What's the difference between ^ (caret) and ~ (tilde)?

^1.2.3 matches >=1.2.3 and <2.0.0 (allows minor and patch changes). ~1.2.3 matches >=1.2.3 and <1.3.0 (allows patch changes only). These are the most common range syntaxes in npm package.json files.

What are prerelease versions and build metadata?

Prerelease versions like 1.0.0-alpha.1 indicate testing versions before the main release and have lower precedence than the release version. Build metadata like 1.0.0+build.2024 is for build differentiation only and is ignored during version comparison.

Why is "v1.0.0" not valid SemVer?

The SemVer specification requires version numbers to be pure numeric with dots — the "v" prefix is not allowed. "v1.0.0" is common in Git tags but is not a valid semantic version. This tool automatically strips the v prefix for parsing and notifies you.

How do I use this SemVer Validator?

Enter any version string in the validation area and click Validate. You can validate a single version, compare two versions to see what type of change occurred, test npm-style range matching, or batch-validate multiple versions at once. All processing happens locally in your browser.
