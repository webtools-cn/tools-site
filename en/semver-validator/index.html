📖 What is SemVer?

Semantic Versioning (SemVer) is a software versioning specification with format MAJOR.MINOR.PATCH:

  • MAJOR: Increments for incompatible API changes
  • MINOR: Increments for backward-compatible new functionality
  • PATCH: Increments for backward-compatible bug fixes
  • Pre-release label: Optional, e.g., -alpha, -beta.1
  • Build metadata: Optional, e.g., +build.123

Full spec at semver.org

❓ FAQ

Q: How to check if a version is valid?

A valid version must follow MAJOR.MINOR.PATCH format. MAJOR/MINOR/PATCH must be non-negative integers without leading zeros. Pre-release labels start with a hyphen, build metadata starts with a plus sign.

Q: What are the comparison rules?

Compare MAJOR first, then MINOR, then PATCH. Versions with pre-release tags rank lower than normal versions. Pre-release labels are compared dot by dot: numeric identifiers by value, string identifiers alphabetically.

Q: What do npm ^ and ~ ranges mean?

^1.2.3 means compatible updates, allowing >=1.2.3 <2.0.0; ~1.2.3 means patch updates, allowing >=1.2.3 <1.3.0. Use the "NPM Range Check" section above for quick verification.

Q: What version formats are supported?

Strict mode only accepts standard MAJOR.MINOR.PATCH format. Loose mode additionally supports v1.0.0, 1.0, and 1.
