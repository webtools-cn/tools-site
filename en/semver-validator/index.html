❓ FAQ

What is Semantic Versioning (SemVer)?

Semantic Versioning is a versioning scheme using the MAJOR.MINOR.PATCH format. Increment MAJOR for incompatible API changes, MINOR for backward-compatible new features, and PATCH for backward-compatible bug fixes. See semver.org for the full specification.

What are prerelease versions and build metadata?

Prerelease versions like 1.0.0-alpha.1 indicate testing versions before the main release. Build metadata like 1.0.0+build.2024 is for build differentiation only and does not affect version precedence. Build metadata is ignored when comparing versions.

What's the difference between ^ (caret) and ~ (tilde) ranges?

^1.2.3 matches >=1.2.3 and <2.0.0 (allows minor and patch changes). ~1.2.3 matches >=1.2.3 and <1.3.0 (allows patch changes only). These are the most common range syntaxes in npm package.json files.

Why is "v1.0.0" not valid SemVer?

The SemVer specification requires version numbers to be pure numeric with dots — the "v" prefix is not allowed. "v1.0.0" is common in Git tags but is not a valid semantic version. Our tool will warn you about v-prefixed versions.
