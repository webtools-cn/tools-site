📖 Browser Compatibility Guide

Why browser compatibility matters

Web APIs have different support levels in different browsers. Using an unsupported API can cause your site to fail or break for some users. Compatibility data helps you choose the right APIs and plan polyfills.

Compatibility level descriptions

  • ✅ Supported — the browser version fully supports this API
  • ⚠️ Partial support — supported but with limits or behind a flag
  • ❌ Not supported — the browser version does not support this API

Best practices

  1. Use feature detection instead of browser detection
  2. Provide fallbacks for critical features
  3. Use @supports to detect CSS properties
  4. Follow MDN and caniuse.com for the latest data
  5. Add vendor prefixes with Autoprefixer

📖 FAQ

How do I check a Web API's browser compatibility?

Use the search box above to filter APIs by name or category, then click any API to see its Chrome, Firefox, Safari and Edge support details.

Which browsers are covered?

Chrome, Firefox, Safari and Edge. Each entry shows the minimum version that supports the API.

What do the status badges mean?

Green means fully supported, amber means partial support or behind a flag, and red means not supported.

Is my data uploaded to a server?

No. All checking is done locally in your browser and nothing is ever sent to any server.
